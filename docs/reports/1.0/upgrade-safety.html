Retire unsafe legacy remote apply

2026-09-05. Issue #638, native review findings 1 and 5. Base: f4175a5d. Implementation: Codex. Parent release work owns governance, review, CI, and merge.

Remote apply is disabled. This change removes an unsafe deployment path. It does not implement signed upgrade compatibility, durable migration phases, an HA upgrade-generation fence, or a replacement platform controller. Manual verified artifacts and release metadata remain available.

Why this blocks 1.0

The old executor automatically ran rollback after apply or health failure without proving whether schema writes had started. The platform scripts restored the database as part of that rollback. Its local journal did not provide a safe, datastore-owned phase boundary. Separately, the Flux adapter committed and pushed through ambient Git credentials. Shipping those paths while describing the future design as disabled would expose the exact unsafe behavior the design rejects.

Admission boundaries closed

Config and server boot reject legacy enablement. Status always reports unsupported. The authenticated apply service emits a refused attempt and never contacts the helper. hikyo updater refuses before config, socket, or journal access. The helper protocol refuses capability and submission. The executor and direct command runner refuse independently. Compose, systemd, Flux, and their common shell library now exit with the migration-safety reason before any phase, credential read, Git operation, or deployment command.

The OpenAPI descriptions and generated Go/TypeScript comments now describe retirement. Existing response schemas remain wire-compatible; authenticated apply returns HTTP 409 with an explicit reason. Public job backend enums are unchanged. The extra disabled backend value is limited to audit payloads.

Preserved and replaced tests

Removed executor expectations that all phases run and that apply/health failures automatically roll back, plus phase-timeout and progress-write acceptance tied to that retired execution path. Replaced them with all-backend/version refusal, direct runner no-process, and all-shell-phase no-side-effect tests. The old socket preparation test is replaced by helper-startup refusal that preserves socket-path data and a queued journal. Unix submission acceptance becomes protocol refusal plus historical job/outcome read and acknowledgement coverage. Service enqueue acceptance becomes audited conflict with and without a configured control.

Preserved journal persistence, interrupted-history handling, config integrity parsing, stale-auth refusal, historical outcome reconciliation and acknowledgement retry, full runtime audit-emitter coverage on both engines, release-status wire fields, prior job wire shape, job error rendering/polling, signed-download implementation, channel behavior, and unrelated tests. Operator action and limits

Stop and disable existing updater services before installing this release. Check for previously spawned backend commands, preserve the journal and logs, and remove HIKYO_UPDATER_SOCKET. A replacement binary cannot retroactively stop an already running old process. Do not replay queued jobs or assume a legacy apply phase means rollback is safe. Investigate any interrupted apply and use the operator-led recovery procedure.

Follow manual upgrades and signed artifact verification. The helper retirement does not change current automatic-migration behavior or provide the proposed generation fence. Those broader #638 requirements remain separately governed. See the implementation handoff.
