Observed cause

Failed test_core job: all core Go tests passed. MCP conformance then failed because Corepack selected pnpm 11.25.0 from outside a package, while scripts/mcp-conformance/package.json pins 11.24.0. The --dir option reaches pnpm after Corepack chooses its version. Runner teardown also reported an orphaned conformance-server process.

Decision

QuestionOptionsRecommended choice
How should conformance select pnpm?A: enter the owning package before Corepack invocation. B: bump the pin whenever registry latest changes. C: disable strict version checks.A. Both frozen installation and execution use the actual owning package directory. Preserve its pin, lockfile and strict checks.
How should the fixture process stop?A: build and own the server executable directly. B: terminate go run and rely on runner orphan cleanup.A. The script waits for its actual server process and removes the temporary executable on success or failure.

Validation

The original invocation reproduced the exact 11.25.0/11.24.0 refusal locally under Corepack 0.35.0. With that same default version, the fixed package-scoped frozen install passed. Inspector and all three upstream conformance scenarios passed their existing baseline. The baseline remains unchanged; caching checks for unsupported prompts/resources remain explicitly expected failures, not newly supported capabilities.

An injected package-tool failure returned exit 23 without swallowing the failure. TCP port 18080 was closed after both the successful conformance run and the injected failure. ShellCheck, actionlint, the repository cache-policy fixture and git diff whitespace checks passed. Machine-readable evidence.
