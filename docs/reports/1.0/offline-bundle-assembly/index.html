Public upgrade bundle assembly

Implemented an offline, fail-closed assembler at scripts/release/assemble-upgrade. It uses caller-pinned root/recovery public material and existing maintained signature verification. It never signs or generates production custody.

Decisions

  1. Input scope: accept closed directories containing public snapshot, key, stable release and bridge proofs. Refuse extra members, missing proofs, symlinks, FIFOs, escaping locators and duplicate releases. Keep executable verification in the existing release/install process; copying arbitrary downloaded payloads into a public proof bundle would add a second artifact inventory.
  2. Publication: preserve exact signed bytes, generate only the unsigned locator index, authenticate the staged result through the production upgradebundle.Load reader, sync files/directories, then atomically publish with a no-replace rename. Existing and concurrently created outputs survive unchanged. Bounded inputs and aggregate staging limit remain enforced.
  3. Remaining signing dependency: assembly is now executable. Real production metadata/catalog/release signatures still require the release owner's signing ceremony. This tool does not supply that authority or implement platform apply.
  4. Kubernetes custody: state PVC root must have gid 65532 and mode 2770; its operator-custody child has uid 65532 and mode 0700. The chart points the gate at that child and pins OnRootMismatch. Kubelet's root permission check requires the setgid bit as well as group permissions. Native/Compose custody remains mode 0700 without Kubernetes permission mutation.

Actual validation

  • go test -race ./scripts/release/assemble-upgrade: passed 20 tests/subtests using real ephemeral signatures. Includes exact-byte preservation, wrong recovery trust, altered proofs, incomplete/extra inventory, symlink with trailing slash, FIFO, signed traversal, catalog bridge omission, rollback floor, cancellation and concurrent publication.
  • go vet ./scripts/release/assemble-upgrade: passed. Linux amd64 test binary cross-compiled successfully; runtime tests above executed on macOS.
  • bash scripts/ci/check-chart_test.sh: valid chart accepted and all 18 targeted mutations refused, including custody-on-volume-root and recursive fsGroup permissions.
  • ShellCheck passed for chart-kind, chart checks and chart mutation fixtures. git diff --check passed.

Real CSI remount behavior and the complete kind deployment are not claimed by these local checks. The runbook requires a driver preserving private child permissions and shared POSIX lock/durability semantics. The parent workflow owns final integration checks, independent review, CI and merge.
