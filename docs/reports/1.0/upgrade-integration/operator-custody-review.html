Operator custody review

Two correctness findings fixed. Recovery and archive imports now retain PostgreSQL exclusion through transaction settlement, including migration-owner backend loss.

Decision recorded

Question: can a pre-commit connection probe establish custody?

OptionDecision
Probe the original backend before commitInsufficient alone: backend can die after the query.
Retain a shared transaction advisory barrier plus probeChosen: the next migration owner drains the barrier before entering, even when the old owner dies.

What changed

The existing goose exclusive session lock remains. A second drain barrier is held by the owner and every recovery/import transaction. Commit validates the original backend and goose lock. Abandoned runtime-DB restore entrypoints and the unused direct emptiness query were removed; the private importer requires verified route and custody checks.

Evidence

Six focused race cases passed, zero skips or failures, using an isolated PostgreSQL test database. Upgrade package: 2.256 seconds. App package: 11.436 seconds. Tests prove recovery rollback, restore rollback, next-owner exclusion after backend termination, and preserved nested goose ownership on both engines.
