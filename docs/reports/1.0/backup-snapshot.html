Backup manifest and snapshot consistency

5 September 2026. Base b3fb04eb87d4a3598e60c071563e47a6ff126264. Existing backup correctness fix; signed-upgrade foundations remain separate.

Observed defect

Export read the live schema version before obtaining the engine snapshot. A concurrent schema change could commit between those operations, leaving the manifest at version44 while the archived database included45. This can misdirect restore schema selection.

Decision

QuestionOptionsChoice and reason
Which schema identity belongs in the manifest?Keep the early live preflight; read the actual archived snapshot; add an unrelated global export lock.Read the actual snapshot. SQLite inspects its owned VACUUM output with a read-only connection. PostgreSQL reads schema version inside its existing serializable read-only deferrable export transaction. The manifest describes exactly the data being exported.
