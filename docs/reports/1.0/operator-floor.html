Operator floor acceptance

Scope: OBL-OPERATOR-PI-FIT, #79. The maintainer's August 20 disposition allows native arm64 cgroup CI evidence; a physical Pi is optional calibration.

Pass criteria

All 50 CRs must produce correctly owned Secrets with all 64 exact values, accept an updated value set, perform an unchanged conditional fetch without rewriting Secrets, retain unchanged Secrets under HTTP 503, and recover. Status must record a fresh fetch in every phase. Missing CRs, stale status, changed retained values or ownership cannot satisfy the evidence checker. Each phase has a 300-second deadline.

The operator must remain ready with zero restarts and zero cgroup OOM events. Its measured peak must be at most 134217728 bytes under an observed 20000/100000 CPU quota; outer node limits must be observed as 400000/100000 and 4294967296 bytes. The harness refuses unsupported architecture or cgroup versions.

Evidence and remaining work

Local native arm64 run passed on September 5, 2026. Peak operator memory was 76185600 bytes (72.66 MiB) under the exact 128 MiB / 200m cap, with zero swap, OOM events and restarts. The five fleet phases completed in 2.60, 3.64, 3.78, 3.73 and 3.68 seconds. The enclosing node had the exact 4 CPU / 4 GiB cap. Docker's Linux VM had only 2.35 GiB of physical memory available; this local run is supplementary evidence, not a claim of physical Pi calibration or a completed GitHub CI gate.

Result and binary identity, operator cgroup, node cgroup, startup and acquired leader lease.

The status ledger remains open until a reviewed release-candidate run produces the passing CI artifact. No resource limit or prior acceptance test has been relaxed. Full operator and evidence-checker tests, scoped vet, ShellCheck and actionlint pass.

Production defect found by measurement

The operator creates a private HTTP client on every reconcile, but kept its idle TLS connections indefinitely. The real-connection regression test failed before the fix. Fetch now closes idle connections after its response body closes, preserving TLS and authorization behavior. Before this fix the non-invasive load run reached 134328320 bytes and 64 memory-limit pressure events; after the fix it reached 76185600 bytes. The shipped memory and CPU limits remain unchanged.

The harness also received two evidence fixes before the result above was accepted: read the target cgroup from the node so the measuring process does not consume operator memory, and clear prior resource files before each run so a failed lookup cannot reuse an older result. Cleanup preserves the single measured snapshot rather than overwriting it after validation.
