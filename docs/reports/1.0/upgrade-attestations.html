Runtime fence integration

Actual SQLite and PostgreSQL legacy, config-only, private-custody and applied-ledger upgrade drills passed in the combined foundation tree (19.123 seconds). The scratch path now uses RecoveryDB under an active migration session and authenticated archive; ordinary runtime services remain unavailable. Existing private service rules supply real authorization, audit, credential policy and mint/revoke behavior.

Decision: ordinary v1 archives receive a distinct data-import capability bound to the actual signed source schema and migration manifest. They do not imply a v2 receipt. Restored serving requires a new export and drill bound to the current recovery incarnation, then acceptance by the gate. The alternative of enabling runtime while constructing proof was rejected because it would bypass the restore barrier.

New race checks cover owner/archive expiry, physical-target mismatch, schema drift and occupied destination preservation. These are in progress and not yet claimed passed. PostgreSQL's initial emptiness check was corrected to use read-only fresh-schema inspection; attempting ordinary runtime Open on the deliberately empty target correctly failed.
