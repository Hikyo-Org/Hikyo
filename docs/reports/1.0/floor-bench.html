Acceptance boundaries

CPU durations multiplied by committed factors are conservative estimates, not measurements on a Pi. Publish must estimate at most 30 seconds; scanner p99 at most 5 ms per 64 KiB item; scanner compilation at most 2 seconds and 32 MiB boot RSS. Boot, KDF and reencrypt timings remain reported measurements with estimates, without new latency limits.

The fixtures use signed development admission and synthetic tenant content. They grant no production release or recovery authority. The operator uses a controlled test TLS delivery source. Existing recovery proofs remain separate.

The required main CI graph includes the planned floor-bench job, its registry and its fail-closed aggregate. A separate secret-free PR trigger proves the new job before the trusted base learns it; all tags run the gate. The release workflow also directly depends on it before building an unsigned draft. This intentionally duplicates the rare release-tag run so an independent failed workflow cannot be ignored by publication. Raw runs emit raw-measurement-only and cannot satisfy required CI.
