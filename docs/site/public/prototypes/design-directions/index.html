design directions

The shipped app reads as generated: rail plus sidebar, every section boxed in a card, identical outlined buttons, ledes restating headings, graphite plus teal. Which structure, not which palette, should replace it? Each direction renders the same two surfaces with the same fixture data: the environment matrix and the projects list. Review on a phone at 390 wide as well as on a desktop; both are primary.

Iteration 2, merged candidate

  • 2BenchLATEST matrixprojects
    Switchboard's structure with a quieter skin: tree sidebar on desktop, org/project plate with a full-screen tree on phone, filter field in a single toolbar row, snap-per-environment horizontal scroll with a channel strip, inspector closed by default (tap a cell), fixed bottom bar for publish state and the primary action, inline legend, light and dark. Hanken Grotesk and Commit Mono.

Iteration 1, three structures

  • 1aConsole matrixprojects
    Terminal surface on the web, dark first. Collapsible text tree for navigation, status line, bottom key strip with accelerators on desktop and plain thumb actions on phone, inverse-video selection, one-line provenance strip. Commit Mono throughout.
  • 1bSwitchboard matrixprojects
    Industrial instrument panel, light first. Single sidebar with org and project switch plates, 2px rules instead of cards, channel column headers with a hatched protected guard, right inspector column, snap-per-environment scroll on phone. Schibsted Grotesk and Martian Mono.
  • 1cLedger matrixprojects
    Grid first, light first. No sidebar: a 44px top bar with surface tabs, a grid toolbar with filter and pending-publish indicator, sticky key column, spreadsheet cursor, inspector pane on demand, environment tabs on phone. Atkinson Hyperlegible Next and Mono.
