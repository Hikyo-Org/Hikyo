# OpenAEV core layer handoff

The authorized migration moves OpenAEV validation to a GitHub-hosted ARM64 runner after release or prerelease publication. Validation is nonblocking. Failure must never append release notes, badges, or result artifacts.

## Stack and ownership

```text
Core PR, base main
  -> #904 assertion suites
  -> #903 hosted runner, native preparation, isolated stack, success-only publisher
```

This core layer imports nine application Python files and eight matching regression modules. It owns bounded recording/reporting transports, adversarial definitions and HTTP transport, load scheduling, native audit checks, native memory/readiness guards, and read-only release identity/count helpers. The HTTP pilot transport is a required import dependency. Only the harness checker workflow is added; this layer adds no live post-release workflow.

Source came from the existing assertion layer. The workload transport explicitly sets its existing TLS 1.2 minimum. Review fixes make ordinary background collector crashes sticky sanitized failures even after a later healthy native read, reject truncated HTTP bodies even when the delivered prefix is complete JSON, retain sanitized reporting schema and size errors while hiding raw transport details, require a nonempty native node UID, and collect six pods at idle and seven during execution. Seven additional regression tests reproduce these failures against the original core head and verify the corrections. Existing adversarial request coverage and all retained core tests remain intact. The middle suite layer retains all 313 native assertions.
