Changes and reasons

  1. Five scheduled/manual entry points become reliability.yml: go-security, gitlab-e2e, reporting-e2e, race-isolation, and security-channel. Original suite steps, cron cadence, native runners, matrices, timeouts, pinned tools, caches, and artifacts remain. Only the fallback-channel job can write issues. Explicit routing rejects unknown events, cron values, and menu choices.
  2. floor-acceptance and operator-floor become release-acceptance.yml. Backup custody secrets remain confined to the existing backup step. The PR-capable ops-floor workflow remains separate from this secret-bearing flow.
  3. Benchmark smoke runs as a step in test_core, immediately after the same packages have been compiled and tested. It still exercises every benchmark in crypto, dotenv, scanning, server, and service once. Its failure now fails a required job. The separate three-iteration scanning guard remains. Relevant changes retain coverage; docs-only changes lose the unrelated cold Go job.
  4. The observed PR gate writes bounded versioned check identifiers. Its old base64-encoded JSON exceeded GitHub's persisted length on long base refs. The replacement retains full commit identities and hashes the complete base ref. Legacy-state recovery only permits invalidation and fresh reassessment; an incomplete old identifier is never success evidence.
  5. Metadata-only validation callbacks skip the observer runner, matching the controller's existing no-op. New-run, in-progress, completed, lifecycle, and scheduled repair events remain. In-progress callbacks matter because GitHub does not send requested events for reruns.
  6. A single CI guide, linked from CONTRIBUTING, explains all 20 remaining files, manual commands, trust boundaries, and gate migration. Active policy/docs references follow the consolidated workflows; historical reports retain their original evidence.

Consolidation improves navigation but adds a small routing job to each maintenance or acceptance run. It does not remove those suites' test execution. Benchmark reuse removes one separately allocated job on relevant PRs and the entire smoke job on irrelevant PRs. These are structural reductions, not measured elapsed-time savings. Smoke adds a short serial step to core tests; the independent local run completed its service benchmarks in 23.1 seconds, excluding other packages and compilation. No tests, security scans, signatures, or paid-run admission gates were removed to make CI green.

Why the polling gate stays for now

The earlier replacement is still called ci-required-next. Hosted observation accepted queued checks and successes, and REST filter=latest selected the newest check. But long stacked Dependabot refs produced exactly 255-byte identifiers containing incomplete JSON. Scheduled reconciliation 38101138824 failed with unexpected EOF for four PRs; 17 of the latest 60 sampled observer runs were failed callbacks. The local identifier repair addresses that proven defect.

Same-head rerun invalidation and recognition as the required repository check remain unproven on GitHub. Ruleset 20539346 still requires the old ci-required, strict current-base status, signatures, and resolved review threads, with no bypass actors. Removing the old polling job and its repair workflow before this proof would be premature. No ruleset changes are part of this patch.

The largest remaining speed opportunity is replacing the runner-held wait with the repaired completion-driven gate. The rollout must demonstrate long-ref publication/readback, stale-success invalidation after rerun/base changes, and required-check recognition before removing the legacy pair. Increasing timeouts, dropping race coverage, or blindly reducing shard count would not fix the measured source of delay. The sampled longest race shard already takes 22.5 minutes against a 30-minute limit.
