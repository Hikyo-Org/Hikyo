# Parked #158 handoff: 2. What the implementation does, and why


The original issue asks for a one-way destination adapter over #157 and #65 ownership semantics. AWS is not a source of truth. Region and account are explicit. Modes are one deterministic JSON object per target or one AWS secret per selected key. Rotation, import/readback as a source, cross-account replication and Secrets Manager resource policies are out of scope.

Provider `aws-secrets-manager` is registered in the closed provider/kind set. Destination columns carry account, name/prefix and optional KMS routing; changing those fields invokes the existing destination-move scrub-before-switch logic. Auth descriptors are strict sealed JSON: ambient, AssumeRole, WebIdentity and static. Ambient/workload use is refused unless node policy `HIKYO_ADAPTER_AWS_WORKLOAD_IDENTITY=allow`; default is deny, so a project admin cannot borrow the server's identity. AssumeRole sessions are 900-3600 seconds. WebIdentity token-file location comes from server configuration. Static descriptors enter only through no-echo prompt, stdin or a protected file. The removed static key identifier flags and `--aws-auth static` fail safely before input/HTTP. Descriptor errors never echo submitted material.

The client is a closed awsJson1.1 implementation over the vetted public-egress HTTP client: TLS1.2+, no proxy or redirects, bounded response and deadline below the worker lease. Official SDK SigV4 and STS credential providers are used; `service/secretsmanager` is deliberately absent. Reflection, signed-operation registry and production AST closure tests forbid `GetSecretValue`, `BatchGetSecretValue`, `GetRandomPassword`, `ForceDeleteWithoutRecovery` and `ListSecretVersionIds` in the adapter. The separate synthetic oracle role can read only test values; the writer explicitly cannot read values.

Each attempt proves account identity, and each described ARN proves region/account. Creation is metadata-only with a stable ClientRequestToken. A value is put under the job-stable token into `HIKYO_PENDING`, then AWSCURRENT is conditionally promoted using the observed prior current version. Hikyo markers and journal are updated after promotion. A concurrent external current version refuses the conditional move. Token identity binds job, target, generation and name; replay of the same outbox job preserves one provider version and repairs only missing ownership metadata. A new job gets a new token.

Ledger ownership is authoritative. `MANAGED_BY_HIKYO` and `HIKYO_VERSION` are metadata witnesses, not a substitute for ledger custody. Untagged/unowned names refuse until artifact/generation/destination/version-bound consent exists. A marker for another target refuses. Already-owned pending deletion can restore. Per-key conflicts and ambiguous/definite failures are reported per name, while auth, rate limit, destination movement and journal/gate failures stop the loop. Prune waits for every desired name to converge. Product prune/teardown uses a 30-day recovery window. Test-fixture force-delete is separately scoped cleanup authority, never product semantics.

AWS auth/KMS denials and expired/invalid credentials map to authentication failure. Throttling/TooManyRequests/RequestLimitExceeded carry bounded retry timing. LimitExceededException is a quota refusal, not an invitation to a blind throttle retry. Other definite4xx, ambiguous5xx/network and safe closed error codes remain distinct. Provider messages and secret material are dropped.

Key production owners: `internal/adapter/awssm/{auth,client,module}.go`, `internal/adapter/aws_names.go`, app adapter factory and workload policy, service/outbox worker, store adoption/recovery queries and migrations. The base adapter migration is 00067. Adoption witness migrations moved during main integration: preserve main's existing migration slots and the current candidate's canonical adoption migration, rather than copying an old standalone migration number over main. Source generated contracts, build compatibility and both datastore engines must move together if migrations actually change.
