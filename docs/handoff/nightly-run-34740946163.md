# Nightly build argument limit

## Failure

[Nightly run 34740946163](https://github.com/Hikyo-Org/Hikyo/actions/runs/34740946163)
failed at source `da5a2c78e2b3bd46c87736be24efd927d75666fe` while
GoReleaser launched Go for `darwin_amd64_v1`:

```text
fork/exec /opt/hostedtoolcache/go/1.27.0/x64/bin/go: argument list too long
```

The compatibility declaration was 97,286 bytes, encoded into 129,716 bytes of
base64. Together with the other linker flags, the single `-ldflags` argument
exceeded Linux's 128 KiB per-argument limit. Larger declarations would also
exceed the per-environment-string limit.

## Change

Both release workflows pass the declaration's file path and SHA-256 to
GoReleaser. Its before hook validates the bounded declaration and digest, then
generates ignored Go source containing the same base64 bytes. Only the digest
travels through the release linker. Runtime parsing, digest verification, and
the eight nightly predecessor paths are unchanged.

The hook removes stale generated source before each build. Missing declarations
fail stable/nightly builds; unstamped snapshots remain supported. Explicit
linker stamps retain precedence for subprocess test fixtures.
