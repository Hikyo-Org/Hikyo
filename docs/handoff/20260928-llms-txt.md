# llms.txt for hikyo.app

## Contract

The docs site publishes the https://llmstxt.org/ surface, all generated at build
time from the Fumadocs page tree so it cannot drift from the sidebar:

- `/llms.txt`: title, one-line summary, and every page (title, URL, description)
  in sidebar order, rendered by Fumadocs `llms(source).indexNode()`. Links are
  made absolute against Astro `site` so the file stands alone off hikyo.app.
- `/llms-full.txt`: every page's Markdown concatenated (`docsLlms.full()`).
- `<page-url>.md` (for example `/docs/getting-started.md`): one page's Markdown
  (`docsLlms.page()`), each headed `# Title (url)` plus the description.

## Module boundary

- `astro.config.mjs` adds `remarkLLMs` (`headingIds: false`), which makes every
  MDX module export `_markdown`: the body with ESM dropped. MDX components stay
  as JSX (Fumadocs default), so `<Card title href>` links survive.
- `src/lib/source.ts` owns `docsLlms`. `renderPage` reads `_markdown` through
  `import.meta.glob` keyed by the collection entry's `filePath`, and throws when
  an MDX page has none. Plain `.md` pages (the generated license) use the raw
  body, which is already Markdown.
- The llms.txt summary is a constant in `src/pages/llms.txt.ts`, not a root
  `meta.json` description: that field is serialized into every page's
  hydration props.
- Requires `fumadocs-core` >= 16.15.x with `llms().full()/page()`; bumped
  `fumadocs-core` and `fumadocs-ui` 16.15.0 -> 16.15.15 in lockstep.

## Evidence

`scripts/test-llms.mjs` (in `pnpm run test`) checks that every page linked from
`dist/llms.txt` is absolute and has a non-empty `.md` twin with the expected heading and that
the heading appears in `llms-full.txt`.

## Validation

```sh
cd docs/site
pnpm run check
pnpm run test
```
