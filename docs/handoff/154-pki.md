## Decisions (and divergences from the issue comment)

1. **Scope** as the comment recommended: instance issuers (`pki_issuers`, one
   row per key version, `(name, version)`), instance profiles
   (`pki_profiles`, canonical JSON policy) with explicit project or
   environment **bindings** (`pki_profile_bindings`), environment
   certificates (`pki_certificates`). CA private keys are stored sealed and
   non-exportable; generated leaf private keys are never stored.
2. **Capability** `issue-certificate` (the comment's `pki-issue`, renamed to
   the verb-noun style of the atom table) at environment depth, admitted for
   workload and automation. **Divergence:** the machine opt-in is a field of
   the *profile* (`machine_issuance`), not of the project, because the
   profile is the unit an operator reasons about. It has the uniform
   not-found shape of `machine_reveal`.
3. **Human ceremony:** generated-key issuance reuses the env-bound mint
   ceremony (`NewMintReauthIntent(env, nil)`) exactly as the dynamic lease
   mint does. **Divergence:** no new ceremony purpose, so the five touch
   points of #151 stay untouched. A CSR issuance discloses nothing and needs
   no ceremony.
4. **Offline root:** Hikyo generates the intermediate key and a CSR
   (`pending`), the operator signs offline, `install` activates it. This keeps
   the intermediate key inside Hikyo even when the root is offline (stronger
   than the comment's `import --cert-file` alone). `import` also exists for
   migrating an existing intermediate, as protected input.
5. **CRL:** authenticated, as the comment recommended: operators through
   `pki-issuer.inspect`, environment readers through `certificate.inspect`
   (`read@environment`, audited-none, the `lease.inspect` shape). Issuers
   carry an optional `crl_distribution_url` embedded into leaves; operators
   publish the CRL there. Unknown certificates are listed as revoked.
6. **Profile policy language:** not regular expressions (the comment said
   "regex allowlists"). **Divergence, deliberate:** regex containment is
   undecidable in general, so "widening policy changes fail closed" could only
   be approximated. Patterns are exact names, `*.suffix` (one label), CIDRs,
   exact URIs and `prefix/*`; `pki.Narrows` decides containment exactly and a
   fuzz target (`FuzzNarrowsSound`) checks its soundness.
   Request URIs must be canonical (no query, fragment, opaque form, dot
   segment or alternate spelling) before the prefix match, so a relying party
   that normalizes cannot land outside the pattern.
7. **Issuance is two-phase, fenced on the issuer:** Tx1 reserves the serial
   (`issuing`) and writes the INTENT; the leaf is signed outside any
   transaction; Tx2 re-authorizes, re-applies the caller gate and runs
   `FenceIssuance` (a conditional write on the issuer row that fails when the
   version is no longer active or is held) before recording the leaf. A row
   left `issuing` past two minutes becomes `unknown` and is put on the CRL.
8. **Worker:** `app.pkiWorker`, every node, row-level CAS only (no singleton
   scheduler lease), the dynamic-worker argument. CRL number is
   `max(previous + 1, unix seconds)` so it stays monotonic across a restore.
9. **Restore:** `CompleteRestore` calls `HoldRestoredPKIIssuers` (guarded on
   the table existing, since archives from before migration 00064 are still
   admitted); `pki issuer release-hold` lifts the hold.
10. **Multi-node HA / HSM / KMIP:** no provider seam was added; the signer is
    the in-process `crypto.Signer`. An HSM seam is an ADR amendment.

## PR #825 reconciliation review

Preserved the original signed history and merged main, including the SSH
certificate surface. PKI migration is reserved as 00064 in both engines;
the legacy upgrade drill's explicit ledger and cleanup use the same version.
CA keys are sealed and stored; generated leaf keys are never persisted.

Ordinary adversarial review reproduced and fixed two issuance-boundary bugs:
self-issued CA imports now verify their own signature even when repeated in
the supplied chain, and incompatible leaf key usages are refused rather than
silently replaced with digital-signature authority. Policy preflight and the
signer both enforce the latter. Regression tests cover both refusals.
Cross-provider review was skipped centrally because quota was unconfirmed.

Integrated the reviewed #822 Cloudflare and #823 Vault KV branches before PKI:
the combined migration chain ends at 00064. Regenerated compatibility from a
fresh PostgreSQL database and retained all three providers in the schema.
