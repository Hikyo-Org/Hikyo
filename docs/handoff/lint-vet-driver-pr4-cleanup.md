# Lint vet driver PR 4: remove the go/packages harness

Work: PR 4 of `docs/adr/lint-analysis-driver.md` (branch `dunky13/lint-vettool-cleanup`, stacked on `dunky13/lint-vettool-rawsql`, PR #1487, which stacks on #1483 and #1464). This is the last PR of the stack. The ADR's step 4 amendment is proposed, not owner-accepted.

## Result

- **Removed.** `LoadRepo`, `LoadRepoIn`, `Load`, `LoadIn`, the per-context caches, `flatten`, `RunOver` and `Result`, every old `Check*` entry point and `Check.OnDisk`, `diskInputs`, `ProductionOnly`, the `Test*Repo` loops, and the parity legs (`TestVetDriverParity`, `requireRawSQLParity`, the fixtures' `old`/`oldIn` legs). Line delta against the base branch `dunky13/lint-vettool-rawsql` (this PR's first commit is `a781d3389`): 67 files, +1,225 and -2,156 lines (`git diff --shortstat origin/dunky13/lint-vettool-rawsql...HEAD` at `50e5d645b`, merge base `8100d4f20`; the review fixes touch comments in many files, and the base branch has since advanced with a dev merge, so a rebase may change the numbers). The first review measured 53 files, +861 -1,997 at `cab12f9e5`.
- **Kept.** `Contexts` and the `BuildContext` helpers (`Env`, `Overlay`, `WriteOverlay`), because the vet driver and the fixtures use them. `osSource` (documented deviation from the ADR's step 2): the exported helpers outside the vet driver and `checkUnanalyzedGoFiles`, which runs in the test process, still read the disk. A proposed amendment, not an accepted decision.
- **`internal/isolation` callers.** `TestInvariant07`, `08`, `09a`, `09`, `09b`, `TestInvariantAuditAppendOnly` and `TestInvariantAuditRedaction` were thin wrappers over analyzers that `TestVetDriverRepo` already runs over the whole module under every context (it fails on any finding and on an unanalyzed target package). They are deleted, with a comment where each sat naming the analyzer that now owns the invariant. No invariant is dropped. `TestInvariant12CacheDiscipline` is not an analyzer: its sweep now walks the module with `go/parser` (`packageScopeNames`), over every file whatever its build constraints, test files included, so it reads more than the old default-context load did.
- **Release record.** `docs/release/acceptance-1.0.md` row A6 named `TestSensitiveFormattingRepo` and `TestInvariantAuditRedaction`; both are replaced by `TestVetDriverRepo`, because `scripts/ci/qualification` refuses an acceptance row that names a missing test. The historical 2026-09-05 evidence is untouched; a dated 2026-11-21 note under the table says it ran the old tests and that `TestVetDriverRepo` runs in the `test` lane (the serial `internal/lint` step and `ci-invariants.yml`), not the `race` lane.
- **Reviewed-pin updater.** `TestUpdateReviewedPins` runs the vet tool once per context with `-rawsql.dump -rawsql.native=linux`. The pass reports `rawdump` summaries (`fn <key> <hash>` for each protocol owner and reviewed caller, `dep <owner> <helper> <hash>` for each helper an owner reaches), the test rewrites the pins from them, and then verifies the result with `rawSQLSummaryFindings` for each context. `checkReviewedPinAuthorities` and its tests are unchanged, so the updater still refuses new owners, callers and helpers. Run on the repository it left the pins byte-identical (518.7 s).
- **Test adapter.** `analyzer_helpers_test.go` holds the only `go/packages` use left: `loadFixture` (a handful of type-checked packages), `loadWithSources` (one package with file contents swapped in memory through `Config.ParseFile`), `runAnalyzer` (one analyzer over them) and `checkRawSQL` (the RawSQL pass with facts flowing dependency to importer, then the summary aggregate). The typed-fixture RawSQL, MCP fixture, alert collector, artifact harness and driver-handle tests use them. It also holds test-only copies of `rawSQLDeclarations`, `rawSQLDependencies` and `rawSQLBodyHash`, kept as an oracle that is independent only for dependency traversal: `rawSQLBodyHash` calls the production `rawSQLBodyHashOf`, so the body hashes themselves are not cross-checked (production code uses the facts).
- **CI definitions (separate commit).** The `race-analyzers` group in `reliability.yml` listed the isolation tests that called `LoadRepo`. Its members are now the tests that reach `packageScopeNames`, directly or through the package's own functions or function values, which `scripts/ci/race_isolation_workflow_test.go` discovers with a syntactic heuristic (reflection or another package's function value would escape it): `TestInvariant12CacheDiscipline` and the sweep's cheap temp-tree test, `TestPackageScopeNamesSkipsNestedTreesButSweepsIgnoredFiles`, so the planner list names both. The race-shard exclusion for `internal/lint` is untouched.

### Memory (process tree of the `go test` invocation only)

Method: the queued command is started, the `go test` PID is found by its command line, and `ps -o pid=,ppid=,rss=,comm=` is sampled every 0.5 s. RSS is summed over that PID and its descendants (walking `ppid`), and the maximum sum and the largest single process are recorded. Cold means a freshly built vet tool binary (a unique `-ldflags` value, so no cached vet result applies); `go clean -cache` was not used, so the compiler cache was warm. Warm reuses the cached vet results.
