CI throughput trial: PR #916

The hosted pilot supports adopting single-pass shard planning and retaining the existing trusted-main compiler cache. Compiling a race-test binary once is promising within each existing runner, but transferring it to a separate runner did not establish a latency win. No extra runner capacity, paid service, review bypass or reduced test inventory is proposed.

The hosted pilot concluded on 2026-10-14 with all four experiment jobs passing. The temporary experiment workflow, Python harness and cache-policy exception were removed. The production change is single-pass planning with a trusted-base migration. This report records that experiment and its source revisions; current review, validation and delivery status belongs to PR #916.

Production change and trust boundaries

The all planner command emits complete race, fuzz and isolation plans after one package-inventory read. Individual planner modes remain available. CI loads planner code from the trusted base, builds it once and checks its protocol capability. The first candidate permits fallback only to the exact known legacy source digest. Unknown source, failed bulk execution, malformed JSON and empty shards fail closed. Once the reviewed bulk planner is on the trusted base, CI uses its single-pass protocol.

Current main e5baadde8c0d8d393dabc27003bf125fd48444f2 adds security validation and release-tag handling. The conflict resolution retains both sets of inventory checks and mutation regressions. It also retains main's release caller guard and tag-ancestry validation. The planner fixture now covers the inherited release-tag execution path while leaving the original legacy fixture and frozen coverage fingerprints unchanged. Hosted timing claims above remain bound to the earlier measured source; they are not timings for main's expanded security inventory.
